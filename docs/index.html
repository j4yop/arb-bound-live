arb-bound-live

Live MCX gold bhavcopy fetched through TinyFish, normalised, and judged against a bound derived from contract specifications — fitted to nothing, so it can disagree with the data.

The premise. mcxindia.com returns HTTP 403 (Akamai) from a datacentre IP. curl on the exact URL this reads gets a block page. TinyFish runs a real browser with stealth and rotating proxies, and does not.

G4 is the decisive one: the circular archive is JS-driven and its endpoint sits behind a MIME-blocked JS file, so the parent project could never reach it and had to close a research question with a third-party mirror. The Agent set the archive's From/To dates, clicked Show, and paged through all 14 result pages. The full 204-row result is committed with its run id.

Run it yourself

cp .env.example .env        # key from agent.tinyfish.ai/api-keys
pip install -e ".[server,dev]"

python -m mcx_live live                                     # fetch, parse, bound, verdict
python -m mcx_live circulars 01/10/2024 31/12/2024           # the dated archive
bash scripts/smoke_live.sh                                 # end-to-end, prints a table

uvicorn mcx_live.server:app --reload                       # /health  /scan  /circulars
python scripts/build_dashboard.py                          # regenerate this page

Honest limits

  • ?date= on the bhavcopy URL is ignored — this is a daily ingest, not a historical backfill.
  • Fetch is not perfectly stable on that endpoint; it sometimes returns an HTML shell, so the fetch retries and recovers the payload.
  • Settlement prices are not executable fills. A gap inside a printed band is an upper bound on a trade, not evidence of one.
  • One day is not a persistent edge. The table above is whichever scan is newest; the history table is what can eventually settle it.
