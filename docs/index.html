arb-bound-live

Live MCX gold bhavcopy fetched through TinyFish, normalised, and judged against a bound derived from contract specifications — fitted to nothing, so it can disagree with the data.

The premise. mcxindia.com returns HTTP 403 (Akamai) from a datacentre IP. curl on the exact URL above gets a block page. TinyFish runs a real browser with stealth and rotating proxies, and does not. Everything below is data arrived at that way.

What the Agent run settled

The circular archive is JS-driven and its endpoint sits behind a MIME-blocked JS file, so the parent project could never reach it — an open research question had to be closed with a third-party mirror. The Agent set the archive's From/To dates, clicked Show, and paged through all 14 result pages. Circular #858 — Commencement of Futures Trading in Gold Petal April 2025 Contract, 31 Dec 2024 — is in the returned set, and the whole 204-row result is committed with its run id.

Run it yourself

cp .env.example .env        # key from agent.tinyfish.ai/api-keys
pip install -e ".[server,dev]"

python -m mcx_live wallet                                  # balance + rates
python -m mcx_live live                                     # fetch, parse, bound, verdict
python -m mcx_live circulars 01/10/2024 31/12/2024          # the dated archive

uvicorn mcx_live.server:app --reload                       # /health  /scan  /circulars

Reading the verdict

  • Every pair's bound is a band, not a point — because mint cost, the duty wedge and friction are each stated as ranges, and swept rather than guessed.
  • Only the tradeable direction counts. Fabrication is one-way: small bars are always dearer per gram, so the gap that means anything is the small bar being unusually cheap to obtain by splitting a larger one. abs(residual) would manufacture hundreds of false breaches.
  • A single day is not a persistent edge. One day gives one row per symbol, so one run proves ingest, not inference. The daily workflow is what builds the corpus that can answer it.

Honest limits

  • ?date= on the bhavcopy URL is ignored — this is a daily ingest, not a historical backfill.
  • Fetch is not perfectly stable on that endpoint; it sometimes returns an HTML shell, so the fetch retries and recovers the payload.
  • Settlement prices are not executable fills. A gap inside a printed band is an upper bound on a trade, not evidence of one.
